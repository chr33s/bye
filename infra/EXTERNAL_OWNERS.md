# Infrastructure gaps and external owners (Alchemy 2.0.0-beta.79)

Checked against `node_modules/alchemy/src` at the pinned release. Nothing here is faked in the stack.

| Gap / resource                                        | Status at beta.79                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Owner and plan                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Cloudflare.state({ noTrack: true })` from spec §15.3 | `Cloudflare.state()` takes **no options**. Account-hash annotation is suppressed only through `NO_TRACK=1`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Deploy scripts and CI set `NO_TRACK=1`, `DO_NOT_TRACK=1`, `ALCHEMY_TELEMETRY_DISABLED=1`.                                                                                                                                                                                                                                                                                                                                                               |
| State-store OTLP exporter (§15.7)                     | No option disables it on the default backend. In the installed beta.79 source (`src/Cloudflare/StateStore/Api.ts`) the exporter layer is commented out, but that is upstream code we neither control nor audit per release.                                                                                                                                                                                                                                                                                                                                                                                                                     | **Resolved when the stack uses the self-hosted HTTP state (`STATE_BACKEND=http`)**: `infra/state/worker.ts` implements alchemy's HTTP state contract v5, is tested against alchemy's own client, and has no egress code (asserted on source and bundle). With the default `Cloudflare.state()`, the profile still depends on the upstream worker; disclose that for the Cloudflare-first profile.                                                       |
| Machine-readable plan output                          | `alchemy plan` renders to the terminal; no JSON plan export in the CLI.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | **Resolved in-repo:** `infra/policies/plan-export.ts` runs Alchemy's own `Stack.plan` engine and normalizes it (`plan-normalize.ts`) into the `plan-policy.ts` shape. CI runs `check:plan` on that export in the preview, steady, destroy and release jobs.                                                                                                                                                                                             |
| Queue message retention / delivery delay settings     | `Queues.Queue` accepts only `name`. DLQ is supported via `Consumer.deadLetterQueue`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Defaults apply; journals/outboxes remain the durable record (§6).                                                                                                                                                                                                                                                                                                                                                                                       |
| Bucket protection                                     | `forceDestroy: false` plus `RemovalPolicy.retain(stage.persistent)` (real beta.79 API) on persistent stages. Not a guard against replacement-by-plan.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | `plan-policy.ts` rejects unapproved destructive plans.                                                                                                                                                                                                                                                                                                                                                                                                  |
| Containers (antivirus) — §15.4 media and scans        | Declared: `Cloudflare.Container("Scanner", …)` bound on MailCore as `SCANNER` (container-backed DO class, migration tag v2). Signatures come from the private mirror by default (`SCANNER_SIGNATURES=mirror`): `SigMirror` Worker + private R2 `ClamSignatures` + cron-started `SigMirrorJob` container running pinned cvdupdate 1.2.0, the single egress point (database.clamav.net). Fallback: `SCANNER_SIGNATURES=baked` with a digest-pinned daily CI image (`.github/workflows/scanner-image.yml`), no runtime egress. Both images build and smoke-test locally with Apple `container`; neither has been built/pushed by `alchemy deploy`. | **Wired:** `workers/core/src/scan.ts` starts the scanner with `enableInternet: false` and `SIGNATURE_MIRROR_URL=http://sigmirror.internal`, and intercepts `sigmirror.internal` to the `SIGMIRROR` service binding (declared in `infra/resources/workers.ts`). The MIME parser container also runs with `enableInternet: false`. Containers cannot allowlist egress hosts, so the job container has general internet access; it holds no customer data. |
| Zone WAF / managed rulesets                           | Zone-scoped; not owned by the application stack.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Foundation stack.                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Custom domains / routes                               | Supported (`domain`); values come from `APP_DOMAIN`/`PUBLIC_DOMAIN` at deploy. Zones are foundation-owned.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Foundation stack owns zones; app stack attaches domains.                                                                                                                                                                                                                                                                                                                                                                                                |
| Customer-domain Email Routing                         | Dynamic per-customer rules are application-provisioned, not IaC (§15.8).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | `ProvisionDomainWorkflow`; stack manages only the service-owned `MAIL_ZONE`.                                                                                                                                                                                                                                                                                                                                                                            |
| Turnstile secret wiring                               | `Turnstile.Widget` outputs `secret`; the stack binds `TURNSTILE_SECRET` from protected config instead of the output to keep MailCore's env static.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Ops copies the widget secret into protected config on creation.                                                                                                                                                                                                                                                                                                                                                                                         |
| Worker Previews (`preview.of`)                        | Private beta; isolated DO state only for the Worker itself.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Previews use full isolated stage graphs (`preview-<n>`) instead.                                                                                                                                                                                                                                                                                                                                                                                        |
| Resolved `@effect/*` family drift                     | alchemy's `>=4.0.0-rc.115` ranges could resolve `@effect/sql-d1`, `@effect/sql-sqlite-do` and `@effect/platform-node-shared` to a different rc than `effect` itself.                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Resolved: `pnpm-workspace.yaml` `overrides` pin the whole family (and `effect`) to `4.0.0`; `check:versions` passes.                                                                                                                                                                                                                                                                                                                                    |
| `observability.redactQueryString`                     | Accepted by the Cloudflare API but **not carried** by beta.79's script upload (`PutScriptMetadataObservability` lacks it), so it was silently dropped.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Removed. Invocation logs (which record full URLs incl. bearer tokens in paths) are disabled; only structured opaque-ID logs are emitted. `infra/tests/worker-bindings.test.ts` guards this.                                                                                                                                                                                                                                                             |
| Provider sent-email previews (§10)                    | No provider API exposes the setting.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Ops: console step per provider account (RUNBOOK "Provider sent-email previews"), attested as `PROVIDER_SENT_PREVIEWS=disabled`; `check-config.ts` refuses staging/prod deploys holding a mail credential without it.                                                                                                                                                                                                                                    |
