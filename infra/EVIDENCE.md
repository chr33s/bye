# §14 evidence register

Spec §14 lists decisions that public documentation cannot settle. This file records, for each one:

- what the repository already demonstrates locally,
- the executable procedure that collects the remaining evidence against a real Cloudflare account and approved providers,
- the pass criteria, and the current status.

Record each run's evidence under `evidence/<date>-<item>/`, in the release artifact bucket, never in git. Include the commit, the lockfile digest and the stage.

**Legend:**

- **Local:** proven in repository tests (Node harness, or real workerd via Miniflare).
- **Open:** needs a real account, provider, or device.

The `BYE_FAULT_INGRESS` fault switch in row 2 is implemented in the inbound handler (`workers/core/src/inbound.ts` `ingressFault`). It affects only `+fault` recipients and is covered by `workers/core/test/ops-sandbox-fault.test.ts`. `infra/policies/check-config.ts` refuses it on prod and staging, and CI never maps it (`CI_UNMAPPED`). So it is set by hand, only on a dedicated `dev-*` evidence stage.

Provider sent-email previews (§10) must be off before real mail flows. That is a console step per provider (RUNBOOK "Provider sent-email previews"), attested as `PROVIDER_SENT_PREVIEWS=disabled`, which staging and prod deploys require whenever a mail credential is set. Record the console screenshots under row 1's evidence.

Recovery drills with local evidence:

- state backup/restore (`infra/drills/state-drill.ts`; real-backend procedure in `infra/drills/state-drill-remote.md`);
- data restore (`infra/drills/DATA_RESTORE.md`);
- interrupted deploy (`infra/drills/FAILED_DEPLOY.md`).
